# 0.9.4: Intel VMD ("RAID On") NVMe support

User report: LCOS 0.9.2 could not see the NVMe drive on Dell laptops set to "RAID On"
(SATA operation mode), which places NVMe behind Intel Volume Management Device.

- Kernel: LLK 7.2.6-lcos21 (PR #17, ee74301e, tag 7.2.6-lcos21) adds `CONFIG_VMD=m` and
  `CONFIG_HOTPLUG_PCI_PCIE=y` (both as Debian trixie). lcos20 had VMD off.
- initramfs: initramfs-tools with LCOS `MODULES=most` includes `vmd.ko` automatically
  (verified); no modules-file change. Calamares, GRUB, os-prober: no change; the drive
  appears as a normal `/dev/nvme0n1` (PCI domain 10000:).
- Not covered: real Intel RST RAID arrays (IMSM). Those need mdadm and MD_RAID0/1/10
  (not in LCOS). Users with an actual RST array should switch firmware to AHCI.
- Known VMD risks: some Tiger Lake–Meteor Lake laptops show higher suspend drain or
  resume problems behind VMD vs AHCI.
- Testing: QEMU cannot emulate VMD; needs a real "RAID On" machine (live boot, `lsmod | grep vmd`,
  `lsblk`, install).
