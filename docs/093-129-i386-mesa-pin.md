# #129: i386 Mesa pin (for LCOS 0.9.3)

2026-10-11 CT, editor approved. Not baked, no version bump yet.

- Cause: `lcos-amd-backports.pref` listed Mesa without an architecture. apt applies such a Package line to the native architecture only, so i386 Mesa from excalibur-backports stayed at -1 (the `Package: *` rule). Steam's 32-bit Mesa (25.0.7) could not match amd64 26.1.6 (Multi-Arch: same) and `apt install steam-installer` failed.
- Fix: `config/archives/lcos-amd-backports.pref.{chroot,binary}` add the same Mesa names with `:i386` at 990.
- Source of the installed copy: the ISO's /etc/apt/preferences.d/lcos-amd-backports.pref comes from live-build's `config/archives/*.pref.binary` and is not owned by any package (checked against the 092-02 dpkg database), so upgraders never receive changes to it.
- Fixed at the source: lcos-base now ships `/etc/apt/preferences.d/lcos-amd-backports.pref` (identical to the .binary file). It is deliberately NOT listed in DEBIAN/conffiles, so dpkg overwrites the existing unowned file on upgrade (the Updates tool runs with --force-confold, which would otherwise keep the old file). Keep `config/archives/lcos-amd-backports.pref.binary` and this file identical: live-build removes the .chroot copy at the end of the chroot stage and reinstalls the .binary copy at the same path.
- Done in lcos-base 0.9.3-1 (0.9.3 track open, docs/093-TRACK-OPENED.md).
- Simulated on the 0.9.2 ISO setup with i386 enabled and only this pin change (live overlay, no i386 debs): `steam-installer` 75 new (Recommends off) / 219 new (on), 0 removed, i386 Mesa from backports 26.1.6-1~bpo13+1; a plain upgrade changes nothing.
- The 0.9.2 overlay fix (i386 Mesa debs in lcosrepo1, staging-0.9.2-i386-mesa) covers 0.9.2 systems now; the pin covers the backports source too.
